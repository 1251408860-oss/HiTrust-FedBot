# 第七章 结论与未来工作

说明：本章为中文导师阅览版，作为全文收束章节使用。与前文保持一致，本章不引入超出证据范围的新结论，也不重复铺陈实验细节，而是围绕“本文完成了什么、当前结论应如何理解、下一步最值得推进什么”三个问题进行总结。

## 7.1 研究结论

本文围绕 topology-aware federated bot detection 中的一个核心张力展开，即系统需要在抑制 poisoned participation 的同时保留必要的 semantic group coverage。针对这一问题，本文提出 HiTrust-FedBot，将结构建模、trust-aware filtering、group floor 约束与 hierarchical aggregation 组织为同一条联邦安全控制主线，而不是将它们作为彼此独立的局部技巧进行堆叠。

从方法上看，本文的关键设计不只是采用 `GraphSAGE` 作为主干，也不只是引入一个 trust score，而是把“客户端是否应被保留”“各语义组是否仍被覆盖”“组内与组间应如何聚合”三个原本分散的问题统一到同一训练回路中。这样的设计使本文关注点从传统鲁棒联邦学习中的“如何删掉异常更新”，进一步推进到“如何在过滤恶意参与的同时避免结构语义被静默清空”。

从实验上看，当前证据支持以下几项主要结论。第一，`GraphSAGE` 主线在五个 topology-aware pilot scenarios 上整体稳定成立，说明结构建模在当前任务中确实具有实质价值。第二，在更困难、更加依赖结构信号的场景中，`GraphSAGE` 相比 `FeatureMLP` 给出了更强且更稳定的结果；而在接近饱和的小场景中，这种优势不会被夸大。第三，`trust-aware filtering` 的主要收益不是普遍提高平均 `F1`，而是减少 retained poisoned clients，并在多数设置下把精度代价控制在 `near-neutral` 范围内。第四，静态 `group floor` 虽然是合理的默认折中，但在 fully poisoned small group 条件下存在明确的 principal failure mode。第五，`conditional trust-mass floor` 能对这一主坏点提供有效修复，但其作用应被定位为 targeted hardening，而不是 universal replacement。

因此，本文最稳妥的总体结论并不是“提出了一种在联邦安全场景中普遍优于现有方法的通用防御框架”，而是：针对具有明确结构语义的联邦 Bot 检测任务，本文提出并验证了一条更保守、更可诊断、边界更清楚的安全控制主线。该主线的核心价值在于，它既能在多数设置下明显降低 poisoned participation，又能在主坏点暴露后继续给出可验证的修复方向。

## 7.2 论文的主要启示

本文工作的一个重要启示是，在安全场景中评价联邦防御方法时，不能只盯住平均分类指标。对于本文这一类任务而言，“有多少恶意客户端被继续保留到聚合环节”“某个关键语义组是否在过滤后整体消失”“修复机制是否只是转移退化位置”同样是决定方法是否可信的重要问题。第五章和第六章的结果共同说明，一个更保守但边界清楚的防御机制，往往比一个只在少数平均指标上更好看的方法更有说服力。

第二个启示是，结构信息在联邦安全检测中并不是可有可无的装饰变量。当前结果表明，当客户端关系结构与任务语义具有一致性时，结构建模确实可以改善关键困难场景中的检测质量，并帮助系统更稳定地处理异构客户端带来的学习偏差。换言之，针对 topology-aware 安全任务，把图结构纳入主线并不是“模型更复杂”这么简单，而是问题设定本身的要求。

第三个启示是，任何 group-preserving defence 都应正视其潜在副作用。静态 `group floor` 在平均意义上是必要的，因为它避免了语义组被激进过滤直接抹除；但固定种子机制分析也表明，一旦小组被完全投毒，静态保组本身就会成为新的风险入口。因此，联邦鲁棒设计不能只写“平均上更好”，还必须继续说明“失败条件是什么、如何识别、如何修复、修复后的边界又在哪里”。这也是本文相较于只给平均对照表的工作更进一步的地方。

## 7.3 未来工作

尽管本文已经建立了较完整的证据链，但要把当前工作进一步推进到更强的网络安全期刊标准，后续仍有若干方向值得优先补强。

第一，继续加强外部有效性。当前 held-out `scenario_e` 与 auxiliary public `NSL-KDD` 已经明显提升了实验说服力，但未来仍应进一步引入与主任务语义更接近的公开图安全数据、公开 Bot 数据或跨平台真实场景数据，以验证本文结论是否能在更广泛的数据分布下保持稳定。

第二，扩展攻击面覆盖。当前实验主要聚焦于 `sign_flip` 与 `update_noise` 两类典型更新投毒。后续应系统评估自适应攻击、协同攻击、Sybil 攻击、后门攻击以及面向 trust score 的规避型攻击，从而更完整地刻画本文防御回路的强项、弱点和失效边界。

第三，研究与隐私增强机制兼容的 trust-aware 变体。本文当前默认服务器能够观察并评估单客户端更新，因此与 secure aggregation、差分隐私等更强隐私机制之间仍存在张力。未来若能设计出与隐私增强联邦协议兼容的 trust surrogate 或 group-level defence signal，将显著提升本文方案的实际部署空间。

第四，扩展系统层验证。当前实验规模更适合做机制分析与可复现对照，但对大规模客户端、强异步通信、高掉线率和更复杂 non-IID 分布的覆盖仍然有限。未来需要在更大规模、更接近真实部署条件的环境中继续验证 `GraphSAGE + adapter_ft + trust-aware filtering` 这一主线是否仍然保持同样的稳定性和代价优势。

第五，完善 artifact release 与论文配套材料。当前表图、主结果、场景配置和章节草稿已经形成了较清晰的复现基础。后续若能进一步整理脚本入口、配置模板、结果清单、表图生成流程和关键结论复现路径，并形成更标准的 artifact 包，将有助于增强论文的透明度、可复现性和工程说服力。

需要强调的是，这些未来工作方向并不是对当前工作的否定。相反，它们恰恰建立在本文已经识别出主要收益、主要坏点和主要边界的基础之上。也正因为当前版本已经把“有效性”“失败条件”和“修复方向”同时写清，后续补强才具有明确而高价值的推进路径。

## 7.4 结束语

综合全文可以看到，HiTrust-FedBot 的价值并不在于把联邦 Bot 检测包装成一个追求单一最优指标的模型改进问题，而在于把它重新表述为一个需要同时处理结构建模、恶意参与抑制与语义覆盖保留的安全控制问题。围绕这一问题，本文给出了一条完整且可解释的主线：先用 `GraphSAGE` 建模结构信息，再用 trust-aware filtering 压缩 poisoned participation，用 group floor 维持基本语义覆盖，并在主坏点暴露后通过 `conditional trust-mass floor` 做有针对性的硬化。

对当前版本而言，这样的结尾应保持克制。本文并未证明该框架对所有联邦安全问题普适有效，也未证明任何 hardening 机制都可以无条件推广。但本文已经较为清楚地证明，在 topology-aware federated bot detection 这一具体而重要的问题上，更保守、更可诊断、边界更明确的防御设计是可行的，也是值得继续推进的。这一结论既构成了本文当前最可靠的学术贡献，也为后续进一步补强外部验证、攻击覆盖和部署证据提供了清晰起点。
